# Part 1 [The Review Report]

## Summary

本文提出 LMPool，一个在同机多 GPU LLM 服务中结合 KV-aware routing、NVLink KV copy/move 和版本化事务协议的原型系统，论文最可靠的结论是长共享前缀下的 routing 可以减少未缓存 prefill 并改善服务指标，而 transfer 的结论目前主要是机制正确性和适用边界。

## Strengths

1. 文章对问题的拆分是清楚且有价值的。将 routing 解释为 locality 问题，将 transfer 解释为 fluidity 问题，并明确指出 transfer 不能替代任意负载均衡，这比将所有 KV 复用都归结为“远程缓存”更准确。全局元数据、局部物理所有权、prepare--publish 可见性边界和 move/copy 语义形成了一个可审计的实现模型。

2. 路由实验提供了可重复的正面证据。六张 RTX 3090、五次重复、相同 KV budget 的 5x shared-prefix 设置中，Qwen3-0.6B 的 throughput 从 43.63 增至 48.77 tok/s，Qwen3-1.7B 从 38.22 增至 46.38 tok/s，同时 TTFT、E2E、P90 E2E 和 uncached prefill 均下降。论文同时报告 1x 情况没有稳定收益，这使结论比只展示有利点更可信。

3. 机制证据和负结果的报告较为诚实。microbenchmark 验证了实际 all-layer packed K/V payload 的字节正确性，并测量 1--64-block、三对 NVLink、两个模型的 profile。load skew 中的三次 placement、87 个 copied blocks 和 95 次 lease route 证明了 copy 后的可见性和后续路由；memory skew 中 0.6B 的 source release 被验证，但没有被包装为吞吐量收益。

## Weaknesses (Critical)

1. 论文的系统标题和设计叙事强调 routing 与 NVLink transfer 的组合，但没有证明 transfer 相对于 routing-only 的稳定端到端增益。在 load skew 中，LMPool 相对 routing-only 的 TTFT 和吞吐量有所改善，但相对 round robin 的 0.6B throughput 仍略低，且 mean E2E 更高；在 memory skew 中，0.6B 的 full system 与 routing-only 基本重合，1.7B 也没有满足完整 offload verification predicate。因此，现有数据支持“可执行且受控的 transfer”，不支持“transfer 是 routing 之外已验证的服务性能贡献”。这属于核心证据不足，而不是措辞问题。

2. 评价完全基于内部消融和确定性 synthetic prompts，缺少与至少一个完整生产 serving stack 的同预算比较，也没有公开或匿名多轮 trace 的 replay。routing、load skew 和 memory skew 都明确构造了 prefix exposure、顺序和压力，因此这些实验适合因果定位，但不足以说明在自然到达过程、真实 reuse distance 和真实 decode distribution 下的收益。该问题直接限制 MLSys 评审对外部有效性的判断。

3. 成本模型的设计合理，但缺少将设计选择与结果联系起来的验证。论文报告 pair-specific P95 profile、transaction residual 和 EWMA，却没有 held-out predicted-versus-observed error，也没有比较 no-gate、always-transfer、固定带宽、profile-only 和 profile-plus-EWMA 的 admission outcome。由于 transfer 的服务收益本就不稳定，审稿人无法判断负结果来自工作负载机会不足、成本模型过于保守，还是模型仍然失准。

4. 规模覆盖有限。两个 Qwen3 模型具有相同 KV geometry，硬件限定为单机六张 RTX 3090 和三条直接 NVLink pair，因而没有评估模型 KV geometry、block size、GPU 数或非对称 link 情况变化后路由和 transfer 决策的稳定性。这不是单独的致命错误，但会放大前述外部有效性问题。

## Rating

4/10，Weak Reject。系统机制、实现边界和 routing 证据具有价值，但当前 transfer 的核心服务收益未被稳定验证，且缺少生产级 baseline、真实 trace 和成本模型消融，尚不足以支撑 MLSys 对系统效果与可推广性的要求。

# Part 2 [Strategic Advice]

## 问题根源

第一项问题来自实验结果本身，而不是论文表述。当前 full system 的主要正面效果可由 routing 解释，transfer 的 copy、lease 和 move release 已被观察到，但没有形成独立且稳定的 serving advantage。第二项问题来自 evaluation design 的先天取舍：确定性 synthetic workload 有利于机制归因，却无法替代真实 trace。第三项问题来自成本模型与评估之间缺少闭环，论文解释了 estimator，却没有量化 estimator 是否预测了实际 transaction cost。第四项是原型平台和时间预算导致的规模边界。

## 可救性判断

在不新增实验的情况下，前三项不能通过重写消除。可以补救的是降低主张范围，避免让标题、摘要和 evaluation 结构暗示已经证明 transfer 的普遍 serving speedup。论文已经在 abstract、Q3/Q4 和 limitations 中保留负结果；本次进一步将 Q1 明确为主要端到端性能主张，并将 Q2--Q4 定义为 correctness、protocol 和 boundary evidence。生产 baseline、真实 trace、成本模型 error/ablation 以及扩展规模实验仍是实质性证据缺口，需要新增实验才能解决。

## 行动指南

若投稿前仍可增加实验，优先级应是成本模型消融和 held-out 预测误差，其次是在固定模型、KV budget 和 arrival process 下加入一个 vLLM 或 SGLang baseline，最后是公开多轮 trace 的 replay。成本模型实验应比较 no transfer、always transfer、固定 4-block bandwidth、pair-specific piecewise-linear profile 和 profile plus EWMA，并报告 predicted-versus-observed latency、beneficial-plan acceptance、harmful-plan rejection、throughput 和 TTFT。若没有时间补实验，rebuttal 应坚持三个边界：routing 是已验证的性能结果；transfer transaction、placement lease 和 source release 是已验证的机制；论文不声称 memory pressure、load skew 或任何 NVLink transfer 必然带来吞吐量或 mean E2E 收益。
