SYSTEMS / LLM SERVING 2026

Route for locality. Transfer only when it pays.

LMPool coordinates KV cache across data-parallel LLM replicas. Routing absorbs reusable prefixes when capacity allows; NVLink transfer moves only the blocks whose expected reuse beats movement and disruption.

DESIGN THESIS

A logically coordinated KV pool, not transparent shared HBM.

Each worker remains the physical owner of its blocks and KV tensors.

01 / ARCHITECTURE

One control plane. Many physical KV owners.

The control plane owns global routing and placement metadata. Each GPU keeps its own scheduler, block manager, model runner, and physical KV cache. Only packed K/V tensors cross GPUs over direct NVLink.

02 / MECHANISM

Routing and transfer solve different problems.

01 / ROUTING

Put work near useful state.

The scheduler combines missing prefill, queue work, decode pressure, reclaim cost, and free capacity. A prefix owner can be bypassed when its queue makes recomputation cheaper.

score(rank) = prefill + queue + decode + reclaim − locality
02 / TRANSFER

Move only with a measurable benefit.

Foreground transfer satisfies an actual block shortage; background placement copies hot prefixes ahead of demand. Every plan checks source validity, target capacity, topology, batch size, and saved-prefill ratio.

PREPARE→EXECUTE→PUBLISH→FINALIZE
03 / CONSISTENCY

Never expose incomplete KV state.

Versioned snapshots reject stale metadata. Destination blocks stay hidden until publish. Hash and generation checks reject stale plans; reservations and in-flight markers prevent concurrent reuse.

prepare → execute → publish → finalize / abort
03 / EVIDENCE

Measure each mechanism before combining them.

Routing, transfer, and skew behavior are benchmarked separately. The results support bounded mechanism claims rather than universal transfer superiority.
